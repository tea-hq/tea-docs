## 原生执行不沙箱化

`read`、`write`、`edit` 与 `bash` 以当前 OS 用户身份运行。工作区路径限定与策略审批降低意外范围，
但不会将进程与宿主机、网络、环境、内核、凭据或通过 shell 命令可达的其他用户可读文件隔离。

审批是授权，不是安全保证。对不可信仓库优先使用一次性容器、虚拟机或受限 OS 账户。

## 提示注入

仓库文本是模型输入。`AGENTS.md`、`CLAUDE.md`、源文件、文档、`.tea/settings.json`、提示模板与
`SKILL.md` 内容可能试图覆盖指令或诱导不安全工具使用。项目信任仅控制是否加载本地配置/资源，
不校验其意图。见 [工作区信任](/tea-docs/zh/safety/trust/)。

## 凭据与数据

提供商凭据从 `TEA_*` 环境值解析，不写入已解析设置、事件、会话、SQLite、归档、夹具或常规错误。
见 [凭据](/tea-docs/zh/configuration/credentials/)。

## 工具边界

- 文件路径为工作区相对，并在符号链接与原子替换间重新校验，但可移植文件系统 API 无法消除所有
  TOCTOU 竞态。
- shell 取消拥有并终止派生的进程组（在平台支持时）；硬进程终止可能绕过清理。
- 超长 shell 输出溢出到私有状态目录并返回安全引用。
- 变更开始后的取消是不确定的。重试前请检视工作区。
- 资源、提示、编辑器、子进程、事件与 RPC 缓冲都有显式边界。

## MCP 服务器不沙箱化

MCP stdio 服务器是不可信可执行代码。全局配置或项目信任授权发现与启动，工具审批授权一次宿主声
明的调用。两者都不限制服务器的宿主文件系统、网络、CPU、进程或外部服务权限。见
[MCP 配置](/tea-docs/zh/mcp/configuration/)。

## 终端与自动化

TUI 在正常退出、panic、前台子进程交接与已处理 SIGINT 时按相反顺序恢复已启用终端模式。
`SIGKILL`、宿主崩溃、终端断开与某些平台控制台事件无法运行应用清理。

print、JSON 与 RPC 消费者必须将助手文本与工具输出视为不可信数据。绝不将 JSON 字段或最终答案
作为 shell 代码求值。
